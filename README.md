# GLUAY GLUAY — Mobile-first Video Editor

GLUAY GLUAY is being developed Android-first as a native, local-first video editor. The goal is to import, preview, cut, arrange, subtitle, add effects and export videos on the phone without requiring a cloud backend for basic editing.

## Repository status
This repository contains:
- An initial native Android app shell under `android/` (Kotlin, Jetpack Compose, AndroidX Media3).
- A system video picker and local playback preview as the first Android milestone.
- A Python FastAPI development scaffold under `backend/` for optional transcription/effect experiments.
- A small web/API check page under `frontend/`; this is not the Android editor UI.
- A platform-neutral project schema under `shared/`.

The original Windows v0.3.0 working folder is separate and is not automatically synchronized with this repository. Keep a backup before merging any files.

## Android first milestone
Open the `android/` folder in Android Studio, use JDK 17, install Android SDK Platform 37 / Build Tools 37.0.0, sync Gradle, then run the `app` configuration. See [android/README.md](android/README.md).

Current Android foundation: Home Studio with Room-backed project records, video picker/preview, audio import/extraction/voice-over, and project media metadata persistence. The multitrack editing UI, render pipeline, effects, subtitles and export are still under development.

## Architecture
See [MOBILE_ARCHITECTURE.md](MOBILE_ARCHITECTURE.md). Android editing will use a non-destructive timeline model, Media3 playback/Transformer and Android MediaCodec where supported. Basic editing must not depend on the Python backend or internet access.

## Safety and privacy
- User-selected media remains on-device for the Android editor.
- Do not upload private videos to a cloud service without explicit opt-in.
- Never overwrite original source media during editing.
- Do not claim HDR/10-bit preservation until verified on supported physical devices.


## Implementation progress
- Added `shared/project-schema-v2.json` as an expanded project format covering canvas/export profile, assets, video/audio/text/caption tracks, clip transforms, keyframe/effect/transition placeholders, AI suggestions and proxy/cache references. Schema v1 remains unchanged.
- Added `android/app/src/main/java/com/gluaygluay/editor/timeline/TimelineModels.kt` with a non-destructive in-memory timeline model and pure add/move/trim/delete/split operations. This is an engine foundation, not yet connected to the app UI or persistent project storage.
- These changes have not yet been built or tested on Android. Do not treat them as a finished usable timeline until Room persistence, UI integration, rendering and device tests are complete.

### Project persistence foundation (code added; integration pending)
- Added Room database/entity/DAO and a repository for creating, saving, listing, opening and deleting versioned project documents.
- Added a debounced autosave coordinator for editor state changes.
- Added Room runtime/KTX/compiler dependencies through Kotlin KAPT.
- Current limitation: this persistence layer is not yet wired into MainActivity/editor UI, and no Android build or device test has been run. It is not yet user-accessible from the app screen.

### Home Studio + Room project library (code integrated; build/device verification pending)
- Replaced the initial single-screen entry with a Home Studio project list, create/open/delete actions, and an editor screen.
- Connected the Home Studio to Room-backed project storage and a debounced autosave coordinator.
- Selected video and imported/extracted/recorded audio asset references are written into the project document; audio generated by extraction/recording is now placed in durable app-private project storage rather than cache.
- Added an explicit Save action and restoration of selected media references when reopening a project.
- Important limits: the editor still has no functional multitrack timeline, clip editing UI, audio mixing/export, or actual autosave of every future edit type. Build and physical-device tests remain outstanding; verify document URI permissions and recovery behavior on-device.


### Android build verification
- Added a GitHub Actions workflow to attempt `:app:assembleDebug` with JDK 17, Gradle 8.11.1 and Android SDK 37.
- The workflow result must be checked before treating the source as build-ready. A successful cloud build does not replace testing on the target Vivo device.
- Project metadata now records media durations for imported video/audio assets instead of using an invalid negative source-out timestamp.
